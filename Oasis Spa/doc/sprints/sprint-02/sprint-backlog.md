Sprint Backlog – Sprint 02
1. Objetivo del Sprint (Sprint Goal)

Desarrollar el módulo de registro de usuarios y las funcionalidades iniciales de selección y programación de reservas para el sistema OasisSpa, garantizando la validación de los datos, la disponibilidad de los horarios y la confirmación de las citas.

2. Estimación y planificación (Planning Poker – Fake Poker)

4. Criterios de aceptación del Sprint
El formulario debe validar los campos obligatorios de registro.
El usuario debe aceptar los términos y condiciones para continuar.
El sistema debe validar el código CAPTCHA.
El usuario debe poder seleccionar el servicio que desea reservar.
El calendario debe permitir elegir fechas y horarios disponibles.
El sistema debe impedir la reserva de horarios ocupados.
La confirmación debe mostrar los datos principales de la cita.
5. Entregables esperados

Al finalizar el Sprint 02, se espera contar con:

Formulario de registro de usuarios.
Validaciones de seguridad y aceptación de términos.
Catálogo de servicios de OasisSpa.
Calendario para seleccionar fecha y hora.
Mecanismo de validación de disponibilidad.
Pantalla de confirmación de reservas.
Pruebas funcionales del proceso de reserva.

7. Resultado esperado

El Sprint 02 permitirá establecer la base funcional del sistema OasisSpa mediante el registro de usuarios y el flujo de reservas. Con estas funcionalidades desarrolladas e integradas, el equipo podrá avanzar en el Sprint 03 hacia la implementación de los métodos de pago, las transacciones y las políticas de cancelación y devolución.
